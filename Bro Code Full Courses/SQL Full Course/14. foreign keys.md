# 🔗 MySQL FOREIGN KEYS

A `FOREIGN KEY` is used to create a relationship between two tables.

It ensures that a value in one table refers to an existing value in another table.

Foreign keys are one of the most important concepts when working with **relational databases** because they allow tables to be connected while maintaining data consistency.

---

# Create the Customers Table

First, we need a table containing customers.

Example:

```sql id="q4m8sa"
CREATE TABLE customers
(
    customer_id INT PRIMARY KEY AUTO_INCREMENT,
    first_name VARCHAR(50),
    last_name VARCHAR(50)
);
```

You can view the table with:

```sql id="x7v2kp"
SELECT * FROM customers;
```

---

# Insert Customers

Example:

```sql id="m9w3zt"
INSERT INTO customers
(first_name, last_name)
VALUES
("Fred", "Fish"),
("Larry", "Lobster"),
("Bubble", "Bass");
```

Because `customer_id` uses `AUTO_INCREMENT`, MySQL generates the IDs automatically.

The customers will have IDs such as:

```text id="p2n6vb"
customer_id    first_name    last_name
1              Fred          Fish
2              Larry         Lobster
3              Bubble        Bass
```

---

# Create the Transactions Table

Now we can create a `transactions` table that references the customers.

Example:

```sql id="r8k4lm"
CREATE TABLE transactions
(
    transaction_id INT PRIMARY KEY AUTO_INCREMENT,
    amount DECIMAL(5, 2),
    customer_id INT,
    FOREIGN KEY(customer_id) REFERENCES customers(customer_id)
);
```

The important part is:

```text id="v5q1xa"
FOREIGN KEY(customer_id)
REFERENCES customers(customer_id)
```

This means that `transactions.customer_id` references `customers.customer_id`.

In other words:

> Every `customer_id` stored in `transactions` must refer to an existing customer.

---

# Understanding the Relationship

The two tables are now connected:

```text id="n7m3wd"
customers
┌─────────────┐
│ customer_id │ ←───┐
│ first_name  │     │
│ last_name   │     │
└─────────────┘     │
                    │
transactions        │
┌────────────────┐  │
│ transaction_id │  │
│ amount         │  │
│ customer_id    │ ─┘
└────────────────┘
```

For example:

```text id="c9p2zt"
customers
3 → Bubble Bass

transactions
1000 → 4.99 → customer_id 3
```

This tells us that the transaction belongs to Bubble Bass.

---

# Add a FOREIGN KEY Later

A foreign key does not have to be defined when creating the table.

It can also be added later.

Example:

```sql id="k4x8va"
ALTER TABLE transactions
ADD CONSTRAINT
fk_customer_id
FOREIGN KEY(customer_id) REFERENCES customers(customer_id);
```

Giving the constraint a name such as `fk_customer_id` makes it easier to identify and manage later.

---

# Remove a FOREIGN KEY

A foreign key constraint can be removed with `ALTER TABLE`.

Example:

```sql id="z6p3ma"
ALTER TABLE transactions
DROP FOREIGN KEY transactions_ibfk_1;
```

`transactions_ibfk_1` is the name MySQL assigned to the foreign key constraint.

When creating the foreign key yourself with a name such as `fk_customer_id`, you can use that name when dropping it:

```sql id="q1v8xt"
ALTER TABLE transactions
DROP FOREIGN KEY fk_customer_id;
```

---

# Insert Transactions

After creating the relationship, transactions can reference existing customers.

Example:

```sql id="w4k2np"
INSERT INTO transactions
(amount, customer_id)
VALUES
(4.99, 3),
(2.89, 2),
(3.38, 3),
(4.99, 1);
```

You can view the transactions with:

```sql id="h8m5qa"
SELECT * FROM transactions;
```

Each `customer_id` refers to an existing customer.

---

# FOREIGN KEY Prevents Invalid References

A foreign key prevents you from referencing a customer that does not exist.

For example, if there is no customer with `customer_id = 10`, a transaction cannot use `10` as its `customer_id`.

This protects the database from invalid relationships.

---

# FOREIGN KEY and DELETE

A foreign key can also prevent you from deleting a row that is currently being referenced.

For example:

```sql id="t3v7ld"
DELETE FROM customers
WHERE customer_id = 3;
```

If customer `3` is referenced by a transaction, MySQL will reject the deletion.

❌ The customer cannot be deleted while another table depends on that customer.

This helps prevent **orphaned records** — records that reference something that no longer exists.

---

# Why Are FOREIGN KEYS Important?

Without foreign keys, you could accidentally store invalid relationships:

```text id="m6x2wp"
transactions
transaction_id    customer_id
1000              3
1001              10  ← ❌ customer 10 does not exist
```

With a foreign key, MySQL can prevent this from happening.

Foreign keys therefore provide:

* 🔗 relationships between tables
* 🛡️ data integrity
* 🚫 protection against invalid references
* 🧩 a foundation for more complex database structures

---

# 💡 Quick Summary

| Concept          | Purpose                                         |
| ---------------- | ----------------------------------------------- |
| `PRIMARY KEY`    | Uniquely identifies a row                       |
| `FOREIGN KEY`    | References a row in another table               |
| `REFERENCES`     | Specifies which table and column are referenced |
| `AUTO_INCREMENT` | Automatically generates IDs                     |
| `CONSTRAINT`     | Gives a constraint a manageable name            |

A simple way to remember it:

> 🔑 **PRIMARY KEY** = "Who is this row?"

> 🔗 **FOREIGN KEY** = "Which row in another table is this connected to?"
