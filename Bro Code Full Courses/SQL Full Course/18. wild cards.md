# 🔍 MySQL Wildcards

Wildcards are special characters used with `LIKE` to search for patterns in text.

They are useful when you do not know the exact value you are looking for, but you know part of it.

---

# `%` — Any Number of Characters

The `%` wildcard represents **zero or more characters**.

### Starts with something

```sql
SELECT * FROM employees
WHERE
first_name LIKE "s%";
```

This finds employees whose `first_name` starts with `s`.

For example:

```text
Spongebob
Sandy
Squidward
```

### Contains something

You can also put `%` on both sides:

```sql
WHERE
first_name LIKE "%on%";
```

This would find names containing `on` anywhere in the value.

### Ends with something

```sql
SELECT * FROM employees
WHERE
last_name LIKE "%r";
```

This finds employees whose `last_name` ends with `r`.

For example:

```text
Krabs
Plankton
```

---

# `%` with Dates

Wildcards can also be useful when searching date values by part of the date.

Example:

```sql
SELECT * FROM employees
WHERE
hire_date LIKE "2023%";
```

This finds dates starting with `2023`, meaning dates from the year 2023.

You can also search for a specific month:

```sql
SELECT * FROM employees
WHERE
hire_date LIKE "____-01-__";
```

This finds dates where the month is `01` — January.

---

# `_` — Exactly One Character

The `_` wildcard represents **exactly one character**.

Example:

```sql
SELECT * FROM employees
WHERE
job LIKE "_ook";
```

The `_` represents the first character.

Therefore, this pattern matches:

```text
cook
book
look
```

as long as the value contains exactly four characters and the last three are `ook`.

---

# `_` with Dates

You can use multiple `_` characters to represent multiple unknown characters.

Example:

```sql
SELECT * FROM employees
WHERE
hire_date LIKE "____-01-__";
```

Here:

```text
____ → any 4 characters
01   → January
__   → any 2 characters
```

So it matches dates such as:

```text
2023-01-02
2023-01-15
2023-01-31
```

Another example:

```sql
SELECT * FROM employees
WHERE
hire_date LIKE "____-__-02";
```

This finds dates where the **day is 02**.

For example:

```text
2023-01-02
2023-02-02
2023-03-02
```

---

# Combining `%` and `_`

The two wildcards can also be combined.

Example:

```sql
SELECT * FROM employees
WHERE
job LIKE "_a%";
```

This means:

```text
_  → exactly one character
a  → must be the second character
%  → anything can come after it
```

So it could match values such as:

```text
cashier
janitor
```

depending on the actual job values in the table.

---

# More Examples

### Starts with `"sp"`

```sql
SELECT * FROM employees
WHERE
first_name LIKE "sp%";
```

This finds names beginning with `sp`, such as:

```text
Spongebob
```

### Ends with `"r"`

```sql
SELECT * FROM employees
WHERE
last_name LIKE "%r";
```

The `%` allows any number of characters before the final `r`.

---

# 🧠 `%` vs `_`

The most important difference is how many characters they represent:

| Wildcard | Meaning                 |
| -------- | ----------------------- |
| `%`      | Zero or more characters |
| `_`      | Exactly one character   |

For example:

```text
"s%"
```

means:

> Starts with `s`, followed by anything.

While:

```text
"_ook"
```

means:

> Exactly one character, followed by `ook`.

---

# 💡 Quick Summary

Wildcards are mainly used together with `LIKE` to search for patterns instead of exact values.

```text
%  → any number of characters
_  → exactly one character
```

Some common patterns:

```text
"s%"      → starts with s
"%r"      → ends with r
"%on%"    → contains on
"sp%"     → starts with sp
"_ook"    → one unknown character + ook
"____-01-__" → any year, January, any day
```

Wildcards are especially useful when searching through large amounts of data where an exact value is unknown.
