# 👁️ MySQL VIEWS

A `VIEW` is a **virtual table** based on the result of a `SELECT` query.

Instead of storing a separate copy of the data, a view stores the query itself. When you access the view, MySQL retrieves the current data from the underlying table.

Views are useful when you frequently need the same query or when you want to show only specific columns or rows to a user.

---

# Create a VIEW

You can create a view using `CREATE VIEW`.

Example:

```sql
CREATE VIEW employee_attendance AS
SELECT first_name, last_name
FROM employees;
```

This creates a view called `employee_attendance` that contains the employees' first and last names.

You can then query it like a normal table:

```sql
SELECT * FROM employee_attendance;
```

The result might look like:

```text
first_name    last_name
Eugene        Krabs
Squidward     Tentacles
Spongebob     Squarepants
```

---

# Query a VIEW

A view can be used with other SQL clauses just like a table.

For example:

```sql
SELECT * FROM employee_attendance
ORDER BY last_name ASC;
```

This sorts the data from the view alphabetically by `last_name`.

You can use `WHERE`, `ORDER BY`, `LIMIT`, and other SQL features when querying a view.

---

# Drop a VIEW

A view can be removed with `DROP VIEW`.

Example:

```sql
DROP VIEW employee_attendance;
```

This removes the view itself.

⚠️ Dropping a view does **not** delete the original data from the underlying table.

---

# Creating a Customer Email VIEW

Views can be especially useful when you only want to expose certain columns.

First, we add an `email` column to the `customers` table:

```sql
ALTER TABLE customers
ADD COLUMN
email VARCHAR(50);
```

You can view the table with:

```sql
SELECT * FROM customers;
```

We can then add email addresses to the customers.

For example:

```sql
UPDATE customers
SET email = "FFish@gmail.com"
WHERE customer_id = 1;
```

The same approach can be used to add different email addresses to the other customers.

---

# Create a VIEW for Emails

Now we can create a view that only contains the `email` column.

Example:

```sql
CREATE VIEW customer_emails AS
SELECT email
FROM customers;
```

You can query the view with:

```sql
SELECT * FROM customer_emails;
```

The view only displays the selected column:

```text
email
FFish@gmail.com
...
```

The other customer information is not included in this view.

---

# Views Show Current Data

One important property of a view is that it reflects changes made to the underlying table.

For example, we can add another customer:

```sql
INSERT INTO customers
VALUES
(5, "Pearl", "Krabs", NULL, "PKrabs@gmail.com");
```

We can then check the customers:

```sql
SELECT * FROM customers;
```

And query the view again:

```sql
SELECT * FROM customer_emails;
```

The new customer's email will appear automatically.

You do **not** need to recreate the view.

This happens because the view executes its underlying `SELECT` query against the current data.

---

# 🧠 VIEW vs TABLE

A view may look like a table, but they are fundamentally different.

| TABLE                                       | VIEW                              |
| ------------------------------------------- | --------------------------------- |
| Stores actual data                          | Stores a query                    |
| Data exists independently                   | Data comes from other tables      |
| Can contain inserted rows                   | Usually used to retrieve data     |
| Can be queried                              | Can be queried                    |
| `DROP TABLE` removes the table and its data | `DROP VIEW` removes only the view |

Think of a view as a **saved query that behaves like a virtual table**.

---

# Why Use VIEWS?

Views can make databases easier and safer to work with.

### 🎯 Simplicity

Instead of repeatedly writing a long query, you can save it as a view.

```text
Complex SELECT query
       ↓
      VIEW
       ↓
Simple SELECT
```

### 🔒 Data Protection

A view can expose only the columns that someone needs.

For example:

```text
customers
├── customer_id
├── first_name
├── last_name
├── email
└── other information
```

A view could expose only:

```text
customer_emails
└── email
```

This can help prevent unnecessary data from being exposed.

### 🔄 Always Up to Date

Because a view uses the underlying table's current data, changes to the original table are reflected when the view is queried.

---

# 💡 Quick Summary

```text
CREATE VIEW
→ Create a virtual table from a query

SELECT FROM VIEW
→ Query the saved view

DROP VIEW
→ Remove the view
```

A `VIEW` is essentially a **saved `SELECT` query that can be used like a virtual table**.

It does not normally store a separate copy of the underlying data.
