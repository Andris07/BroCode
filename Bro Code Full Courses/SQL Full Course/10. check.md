# ✅ MySQL CHECK

The `CHECK` constraint ensures that values inserted into a column satisfy a specific condition.

It is useful for preventing invalid data from being stored in a table.

---

# Create a Table with CHECK

You can define a `CHECK` constraint when creating the table.

Example:

```sql
CREATE TABLE employees
(
    employee_id INT,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    hourly_pay DECIMAL(5, 2),
    hire_date DATE,
    CONSTRAINT chk_hourly_pay CHECK (hourly_pay >= 10.00)
);
```

The `chk_hourly_pay` constraint requires the `hourly_pay` value to be at least `10.00`.

You can view the table with:

```sql
SELECT * FROM employees;
```

---

# Add CHECK to an Existing Table

You can also add a `CHECK` constraint after the table has already been created.

Example:

```sql
ALTER TABLE employees
ADD CONSTRAINT
chk_hourly_pay CHECK (hourly_pay >= 10.00);
```

This adds the same rule to the existing table.

You can check the table again with:

```sql
SELECT * FROM employees;
```

---

# Invalid Value

If you try to insert a value that does not satisfy the `CHECK` condition, MySQL will reject the operation.

Example:

```sql
INSERT INTO employees
VALUES
(6, "Sheldon", "Plankton", 5.00, "2023-01-07");
```

The `hourly_pay` value is `5.00`, but the constraint requires it to be at least `10.00`.

❌ The insert will fail.

---

# Valid Value

If the value satisfies the condition, the insert succeeds.

Example:

```sql
INSERT INTO employees
VALUES
(6, "Sheldon", "Plankton", 10.00, "2023-01-07");
```

`10.00` satisfies the condition `hourly_pay >= 10.00`.

✅ The insert succeeds.

You can view the inserted employee with:

```sql
SELECT * FROM employees;
```

---

# Remove a CHECK Constraint

You can remove a `CHECK` constraint with `ALTER TABLE`.

Example:

```sql
ALTER TABLE employees
DROP
CHECK chk_hourly_pay;
```

The `chk_hourly_pay` constraint is now removed.

You can check the table again with:

```sql
SELECT * FROM employees;
```

---

# Important Notes

## `CHECK`

A `CHECK` constraint defines a condition that data must satisfy.

For example:

```text
hourly_pay >= 10.00
```

This means:

* `15.00` → ✅ valid
* `10.00` → ✅ valid
* `5.00` → ❌ invalid

`CHECK` is a **constraint**, not a data type. It helps keep invalid data out of the database.
