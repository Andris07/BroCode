# ⚡ MySQL INDEXES

An `INDEX` is a data structure that helps MySQL **find rows faster** when searching through a table.

Indexes are especially useful for columns that are frequently used in `WHERE`, `JOIN`, or `ORDER BY` clauses.

Without a suitable index, MySQL may need to check many or even all rows in a table.

---

# View Existing INDEXES

You can use `SHOW INDEXES` to see the indexes belonging to a table.

Example:

```sql
SHOW INDEXES FROM customers;
```

This displays information about the table's indexes, including their names and the columns they use.

---

# Create an INDEX

### `CREATE INDEX`

To create an index, use:

```sql
CREATE INDEX last_name_idx
ON customers(last_name);
```

This creates an index named `last_name_idx` for the `last_name` column.

The index can help MySQL find customers by their last name more efficiently.

For example:

```sql
SELECT * FROM customers
WHERE last_name = "Puff";
```

---

# Multiple-Column INDEXES

An index can contain more than one column.

Example:

```sql
CREATE INDEX last_name_first_name_idx
ON customers(last_name, first_name);
```

This creates a **composite index** using both `last_name` and `first_name`.

It can be useful for queries such as:

```sql
SELECT * FROM customers
WHERE last_name = "Puff" AND first_name = "Poppy";
```

---

# ⚠️ Column Order Matters

The order of columns in a composite index is important.

For example:

```sql
CREATE INDEX last_name_first_name_idx
ON customers(last_name, first_name);
```

is different from:

```sql
CREATE INDEX first_name_last_name_idx
ON customers(first_name, last_name);
```

The first index starts with `last_name`, while the second starts with `first_name`.

Think of the index as being organized primarily by its **first column**, then by the following columns.

For example:

```text
(last_name, first_name)
        ↓
   Last name first
        ↓
   First name second
```

Therefore, when designing a composite index, the order of the columns should match the way you commonly search your data.

---

# Drop an INDEX

You can remove an index using `DROP INDEX`.

Example:

```sql
ALTER TABLE customers
DROP INDEX last_name_idx;
```

This removes the `last_name_idx` index.

You can check the remaining indexes with:

```sql
SHOW INDEXES FROM customers;
```

---

# 🧠 Why Are INDEXES Useful?

Imagine a table containing thousands or millions of customers.

Without an index, MySQL may have to search through the rows one by one:

```text
Customer 1
Customer 2
Customer 3
Customer 4
...
Customer 500000
```

With an appropriate index, MySQL has a much more efficient structure for locating the required rows.

This can make searches significantly faster.

---

# ⚠️ INDEX Trade-offs

Indexes are not completely free.

They can:

* 🚀 Make searches faster
* 💾 Require additional storage
* 🐢 Make `INSERT`, `UPDATE`, and `DELETE` operations somewhat slower because indexes may also need to be updated

Because of this, you generally should not create an index on every column.

Indexes are most useful on columns that are frequently searched, joined, sorted, or otherwise used to locate data.
