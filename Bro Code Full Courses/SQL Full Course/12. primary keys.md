# 🔑 MySQL PRIMARY KEY

A `PRIMARY KEY` uniquely identifies each row in a table.

It is one of the most important constraints in a relational database because it provides a reliable way to identify and access individual records.

A primary key must:

* 🔢 contain a unique value
* 🚫 never be `NULL`
* 🎯 identify exactly one row

---

# Create a Table with PRIMARY KEY

You can define a primary key when creating a table.

Example:

```sql
CREATE TABLE transactions
(
    transaction_id INT PRIMARY KEY,
    amount DECIMAL(5, 2)
);
```

Here, `transaction_id` is the primary key.

You can view the table with:

```sql
SELECT * FROM transactions;
```

---

# Add PRIMARY KEY to an Existing Table

A primary key can also be added after the table has been created.

Example:

```sql
ALTER TABLE transactions
ADD CONSTRAINT
PRIMARY KEY(transaction_id);
```

You can check the table again with:

```sql
SELECT * FROM transactions;
```

---

# Only One PRIMARY KEY

A table can have only **one primary key**.

Trying to add another primary key will result in an error.

Example:

```sql
ALTER TABLE transactions
ADD CONSTRAINT
PRIMARY KEY(amount);
```

❌ This fails because the table already has a primary key.

The primary key can contain multiple columns, but there is still only one primary key constraint per table.

---

# Insert Data

You can insert transactions normally as long as their primary key values are valid.

Example:

```sql
INSERT INTO transactions
VALUES
(1000, 4.99),
(1001, 2.89);
```

You can view the transactions with:

```sql
SELECT * FROM transactions;
```

---

# Duplicate PRIMARY KEY

A primary key value cannot be used by multiple rows.

Example:

```sql
INSERT INTO transactions
VALUES
(1001, 3.38);
```

❌ This fails because `1001` is already being used as a `transaction_id`.

---

# Valid PRIMARY KEY

Using a different `transaction_id` works correctly.

Example:

```sql
INSERT INTO transactions
VALUES
(1002, 3.38);
```

✅ This succeeds because `1002` is not already being used.

---

# PRIMARY KEY Cannot Be NULL

A primary key can never contain `NULL`.

Example:

```sql
INSERT INTO transactions
VALUES
(NULL, 4.99);
```

❌ This fails because `transaction_id` is the primary key and primary keys cannot be `NULL`.

---

# Duplicate Values in Other Columns Are Allowed

Only the primary key needs to be unique.

For example, two transactions can have the same `amount` as long as their `transaction_id` values are different.

Example:

```sql
INSERT INTO transactions
VALUES
(1003, 4.99);
```

✅ This succeeds even though `4.99` is already used by another transaction.

---

# Find a Specific Row

Because the primary key uniquely identifies a row, it is very useful when retrieving specific data.

Example:

```sql
SELECT amount
FROM transactions
WHERE transaction_id = 1003;
```

This finds the transaction with `transaction_id` `1003` and returns its `amount`.

---

# Why Are PRIMARY KEYS Important?

Imagine a table containing thousands or millions of records.

You need a reliable way to distinguish one row from every other row.

A primary key provides exactly that.

For example:

```text
transaction_id
1000
1001
1002
1003
```

Each transaction has its own unique identifier.

This becomes especially important when tables are connected through **relationships**.

Later, primary keys can be referenced by **foreign keys**, allowing tables to be connected to each other.

For example:

```text
customers
    ↓
customer_id

transactions
    ↓
transaction_id
customer_id
```

This allows a database to determine which customer a transaction belongs to.

---

# PRIMARY KEY vs UNIQUE

A primary key is similar to a `UNIQUE` constraint because both prevent duplicate values.

However, a primary key also **cannot contain `NULL`** and serves as the table's main identifier.

| `PRIMARY KEY`                       | `UNIQUE`                               |
| ----------------------------------- | -------------------------------------- |
| Must be unique                      | Must be unique                         |
| Cannot contain `NULL`               | Can allow `NULL`                       |
| Only one per table                  | Multiple allowed                       |
| Main identifier of a row            | Enforces uniqueness                    |
| Commonly referenced by foreign keys | Can also be referenced by foreign keys |

You can think of a `PRIMARY KEY` as a `UNIQUE` constraint with an additional layer of importance and protection.

It does not just say:

> "These values must be different."

It also says:

> "This value is the unique identity of this row."

---

# 💡 Quick Summary

A `PRIMARY KEY`:

* 🔑 uniquely identifies each row
* 🚫 cannot contain `NULL`
* 🔄 cannot contain duplicate values
* 1️⃣ only one primary key can exist per table
* 🔗 is commonly used to create relationships between tables
* 🎯 makes it easy to find a specific record

The primary key is essentially the **identity of a row** in a relational database.
