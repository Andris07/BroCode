# 🔗 MySQL JOINs

`JOIN` statements are used to combine data from multiple tables based on a related column.

They are especially useful when information is split between different tables.

For example, our `transactions` table contains a `customer_id`, while the `customers` table contains the customer's name.

A `JOIN` allows us to combine these pieces of information.

---

# Prepare the Example

First, we add a transaction that is not connected to any customer.

```sql
INSERT INTO transactions
(amount, customer_id)
VALUES
(1.00, NULL);
```

This transaction has no `customer_id`, so it does not have a matching customer.

We can check the transactions with:

```sql
SELECT * FROM transactions;
```

We also add a customer who does not have any transaction.

```sql
INSERT INTO customers
(first_name, last_name)
VALUES
("Poppy", "Puff");
```

You can check the customers with:

```sql
SELECT * FROM customers;
```

Now we have examples of:

* 💳 a transaction without a customer
* 👤 a customer without a transaction

These will help demonstrate the differences between the different types of `JOIN`.

---

# 🟰 INNER JOIN

### `INNER JOIN`

Returns only rows where there is a matching value in **both tables**.

Example:

```sql
SELECT *
FROM transactions INNER JOIN customers
ON
transactions.customer_id = customers.customer_id;
```

The `ON` condition tells MySQL how the two tables are related.

In this case:

```text
transactions.customer_id = customers.customer_id
```

Only transactions with a matching customer are returned.

Therefore:

* ❌ the transaction with `customer_id = NULL` is excluded
* ❌ Poppy Puff is excluded because she has no transaction
* ✅ only matching transactions and customers are returned

---

# Select Specific Columns

You do not have to retrieve every column from both tables.

Example:

```sql
SELECT transaction_id, amount, first_name, last_name
FROM transactions INNER JOIN customers
ON
transactions.customer_id = customers.customer_id;
```

This returns only the information we actually need.

Instead of:

```text
transaction_id
amount
customer_id
first_name
last_name
```

we only retrieve:

```text
transaction_id
amount
first_name
last_name
```

This can make query results easier to read.

---

# ⬅️ LEFT JOIN

### `LEFT JOIN`

Returns **all rows from the left table**, plus matching rows from the right table.

Example:

```sql
SELECT *
FROM transactions LEFT JOIN customers
ON
transactions.customer_id = customers.customer_id;
```

Here, `transactions` is the left table.

Therefore:

* ✅ all transactions are returned
* ✅ matching customers are included
* ⚠️ the transaction without a customer is still returned
* ❌ customers without transactions are not included

When no matching customer exists, the customer's columns contain `NULL`.

---

# ➡️ RIGHT JOIN

### `RIGHT JOIN`

Returns **all rows from the right table**, plus matching rows from the left table.

Example:

```sql
SELECT *
FROM transactions RIGHT JOIN customers
ON
transactions.customer_id = customers.customer_id;
```

Here, `customers` is the right table.

Therefore:

* ✅ all customers are returned
* ✅ matching transactions are included
* ⚠️ Poppy Puff is still returned even though she has no transaction
* ❌ transactions without a matching customer are not included

When no matching transaction exists, the transaction columns contain `NULL`.

---

# 🧠 JOIN Comparison

Imagine the two tables as two groups of data:

```text
transactions          customers
     ↓                    ↓
   LEFT                RIGHT
```

| JOIN         | What it returns                     |
| ------------ | ----------------------------------- |
| `INNER JOIN` | Only matching rows                  |
| `LEFT JOIN`  | All left rows + matching right rows |
| `RIGHT JOIN` | All right rows + matching left rows |

---

# 💡 Easy Way to Remember

### `INNER JOIN`

> "Give me only the things that exist in both tables." 🟰

### `LEFT JOIN`

> "Give me everything from the left table, and whatever matches from the right." ⬅️

### `RIGHT JOIN`

> "Give me everything from the right table, and whatever matches from the left." ➡️

The `ON` clause defines **how the tables are connected**.

In our example:

```sql
ON transactions.customer_id = customers.customer_id
```

This connects each transaction to its corresponding customer.
