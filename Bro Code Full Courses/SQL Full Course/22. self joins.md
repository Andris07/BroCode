# 🔄 MySQL SELF JOIN

A `SELF JOIN` is a join where a table is joined **with itself**.

This is useful when rows in the same table have a relationship with other rows in that same table.

Common examples include:

* 👥 Customer referrals
* 👔 Employees and their supervisors
* 🌳 Hierarchical data
* 🧩 Parent-child relationships

A `SELF JOIN` uses **table aliases** to treat the same table as if it were two separate tables.

---

# Customer Referrals

We can use a `referral_id` column to store which customer referred another customer.

First, add the column:

```sql id="w4n7qa"
ALTER TABLE customers
ADD
referral_id INT;
```

You can view the table with:

```sql id="x2p8lm"
SELECT * FROM customers;
```

---

# Add Referral Relationships

For example, customer `2` was referred by customer `1`:

```sql id="m6v3zt"
UPDATE customers
SET
referral_id = 1
WHERE customer_id = 2;
```

We can create additional referral relationships in the same way.

For example:

```text id="r8k1wp"
Customer 2 → referred by Customer 1
Customer 3 → referred by Customer 2
Customer 4 → referred by Customer 2
```

You can check the relationships with:

```sql id="q5n9xa"
SELECT * FROM customers;
```

---

# INNER JOIN with a SELF JOIN

Now we can join the `customers` table with itself.

Example:

```sql id="v7m2kd"
SELECT
    a.customer_id,
    a.first_name,
    a.last_name,
    CONCAT(b.first_name, " ", b.last_name) AS "referred_by"
FROM
    customers AS a
INNER JOIN
    customers AS b
ON a.referral_id = b.customer_id;
```

Here, the same table is used twice:

```text id="e3p8lm"
customers AS a
customers AS b
```

`a` represents the customer being referred.

`b` represents the customer who made the referral.

The relationship is established with:

```text id="x9q4va"
a.referral_id = b.customer_id
```

The result can look like:

```text id="w2m6zt"
customer_id    first_name    last_name    referred_by
2              Larry         Lobster      Fred Fish
3              Bubble        Bass         Larry Lobster
4              Poppy         Puff         Larry Lobster
```

The `INNER JOIN` only returns customers who have a matching referral.

---

# LEFT JOIN with a SELF JOIN

A `LEFT JOIN` can be used when you want to see **all customers**, including customers who were not referred by anyone.

Example:

```sql id="k8v1qn"
SELECT
    a.customer_id,
    a.first_name,
    a.last_name,
    CONCAT(b.first_name, " ", b.last_name) AS "referred_by"
FROM
    customers AS a
LEFT JOIN
    customers AS b
ON a.referral_id = b.customer_id;
```

Customers without a referral will still appear, but `referred_by` will contain `NULL`.

# Employee Supervisors

A `SELF JOIN` is also useful for hierarchical relationships.

An employee can have another employee as their supervisor.

First, add a `supervisor_id` column:

```sql id="p4m7xa"
ALTER TABLE employees
ADD
supervisor_id INT;
```

You can view the table with:

```sql id="s6q2ln"
SELECT * FROM employees;
```

---

# Add Supervisor Relationships

For example, employee `2` reports to employee `5`:

```sql id="t9w3kp"
UPDATE employees
SET
supervisor_id = 5
WHERE employee_id = 2;
```

Additional relationships can be created in the same way.

For example:

```text id="h5n8vb"
Employee 2 → Supervisor 5
Employee 3 → Supervisor 5
Employee 4 → Supervisor 5
Employee 6 → Supervisor 5
```

We can also make employee `5` report to employee `1`:

```sql id="j2x6qm"
UPDATE employees
SET
supervisor_id = 1
WHERE employee_id = 5;
```

Now the hierarchy looks something like:

```text id="m7q1zp"
Employee 1
└── Employee 5
    ├── Employee 2
    ├── Employee 3
    ├── Employee 4
    └── Employee 6
```

---

# INNER JOIN with Employees

We can use a `SELF JOIN` to display who each employee reports to.

Example:

```sql id="c8v4na"
SELECT
    a.first_name,
    a.last_name,
    CONCAT(b.first_name, " ", b.last_name) AS "reports_to"
FROM
    employees AS a
INNER JOIN
    employees AS b
ON a.supervisor_id = b.employee_id;
```

Here:

```text id="z5m2wd"
a → employee
b → supervisor
```

The relationship is:

```text id="p9x3ka"
a.supervisor_id = b.employee_id
```

So MySQL can turn:

```text
supervisor_id = 5
```

into the actual supervisor's name.

---

# LEFT JOIN with Employees

A `LEFT JOIN` can be used to include employees who do not have a supervisor.

Example:

```sql id="n6q8vt"
SELECT
    a.first_name,
    a.last_name,
    CONCAT(b.first_name, " ", b.last_name) AS "reports_to"
FROM
    employees AS a
LEFT JOIN
    employees AS b
ON a.supervisor_id = b.employee_id;
```

If an employee has no supervisor, the `reports_to` column will contain `NULL`.

This is useful for displaying the **top-level employee** or anyone else without a supervisor.

---

# 🧠 Why Use Table Aliases?

When joining a table with itself, MySQL needs a way to distinguish the two instances of the table.

That's why we use aliases:

```sql
customers AS a
customers AS b
```

or:

```sql
employees AS a
employees AS b
```

Without aliases, it would be difficult for MySQL to know which occurrence of a column you are referring to.

For example:

```text id="e2v7qm"
a.customer_id
b.customer_id
```

Both columns come from the same table, but they represent different roles.

---

# 💡 Quick Summary

A `SELF JOIN` means:

> **Join a table with itself.**

It is useful when rows inside the same table are related to each other.

```text id="u8p3la"
SELF JOIN
    ↓
same table + same table
    ↓
different roles using aliases
```

Common examples:

```text id="r4m9wk"
customers
customer → referred by → customer

employees
employee → reports to → supervisor
```

The important idea is that the table is not actually duplicated. The aliases simply allow us to **treat the same table as two different instances** within the query.
